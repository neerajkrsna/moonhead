Section 00 // First Principles & Problem Statement

Why We Are Creating CORE-OS & What Structural Problems It Solves

Core Objective Structural Problem in Stock Linux Distros CORE-OS Architectural Solution (Option B)
1. Eliminate Userspace & Init Bloat Stock Ubuntu/Debian spend ~250–350 MB of RAM and dozens of background daemons (systemd, journald, D-Bus, snapd) just to boot and parse text unit files. Replace systemd with a memory-safe Rust PID 1 supervisor (~4,500 LOC) using sealed memfd log rings and isolated fs_struct, cutting idle RAM to ~60–75 MB.
2. Survive Extreme Saturation Under 98% RAM pressure, sequential disk backups, or 100% CPU load, dual-list LRU locks and 20% dirty-page writeback stalls spike P99.9 tail latency to 40–300+ ms. Pair upstream Linux 7.3 LTS (MGLRU, RWF_DONTCACHE, sched_ext, resctrl) with a Rust PSI Watchdog (/proc/pressure) that sheds caches in microseconds before direct reclaim blocks apps.
3. Security × Speed Co-Design Hardened clouds disable io_uring via seccomp (hurting async I/O speed) and suffer container path races or heavy sk_buff DDoS drop overhead. Enforce in-kernel BPF io_uring gatekeeping, AF_XDP zero-copy NIC DMA, failfs + fchroot(2) + Landlock FD-only jails, and Intel FRED / ARM MTE hardware protection.
4. Ubuntu Ergonomics & .deb Compatibility Minimalist distros (Buildroot, Alpine/Chimera) break glibc binaries, CUDA/ROCm, or standard /etc/netplan & apt operator muscle memory. Use mmdebstrap --variant=custom + cargo-deb (Provides: init, systemd-sysv) so standard .deb packages, apt, /etc/netplan, and CLI shims work natively with zero systemd.
5. Fast Laptop-VM Build Iteration Yocto requires 32+ cores, 150+ GB disk, and multi-hour full-tree compiles just to test a rootfs or init change. Build inside a modest 6-vCPU / 8–12 GB VM on your MacBook Pro (M5 Pro): mmdebstrap assembles a bootable rootfs in ~30 seconds and incremental Rust/kernel rebuilds take ~20 seconds.

LAYER 3 // mmdebstrap USERLAND
Debian/Ubuntu-Compatible Userland & Hybrid Hot-Path Optimization

Core Engineering Mechanism

Instead of spending 3 hours compiling coreutils, bash, and glibc from source, mmdebstrap --variant=custom resolves and unpacks pre-compiled Ubuntu/Debian .deb packages in ~30 seconds inside a lightweight VM on your M5 Pro MacBook Pro. Performance-critical workloads (databases, proxies, eBPF programs) are compiled from source with LTO/PGO and installed via --customize-hook.

Security & Efficiency Guarantees

  • Server/Edge images pack the rootfs with mkfs.erofs -zlz4hc + veritysetup for immutable read-only A/B boots (~60–75 MB idle RAM).
  • Workstation/HPC images keep dpkg/apt active so standard apt install works out-of-the-box without pulling systemd.
  • Zero daemon bloat: no snapd, no systemd-resolved, no journald, no D-Bus system bus required.

Scrutiny Trade-Off & Constraint

Downstream Debian/Ubuntu packages occasionally declare dependencies on init-system-helpers or systemd-sysv; our coreos-pid1 .deb package cleanly satisfies these virtual packages via Provides/Conflicts metadata.

30-Second mmdebstrap Assembly Command

mmdebstrap --variant=custom --arch=arm64 --include="base-files,base-passwd,bash,coreutils,dash,dpkg,apt,ca-certificates,libc-bin,util-linux,iproute2,nftables,bpftool" --customize-hook='chroot "$1" dpkg -i /tmp/coreos-pid1_0.1.0_arm64.deb' --customize-hook='ln -sf /sbin/coreos-pid1 "$1/sbin/init"' noble ./rootfs-dir
